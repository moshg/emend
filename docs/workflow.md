# 作業の進め方

規約は [conventions.md](conventions.md) に，担当の表など本ごとの事情は本のリポジトリの `docs/book.md` にある．

## 並列作業

章ごとに別のセッション・別のブランチで並列に作業し，最後に 1 本のブランチにまとめてから main にマージする．章とファイルの対応は担当の表に従う（本文のファイル名は `tex/original/` と `tex/revised/` で同じ）．ブランチ同士がぶつからないよう，次を守る．

- **共有ファイルは編集しない**: `tex/main.tex`，`tex/notation.sty`，本の sty，`README.md`，`docs/`，`common/`，`.github/`，`Makefile`．自分の担当のファイル（表の本文・記号・修正のまとめ・`tex/figures/` の担当の図，`make sync` が書く `tex/original-sync.json`）だけを変える．
  - 担当の中だけで必要な書式の調整（付録の番号の付け方など）は，担当の本文ファイルの中に `\makeatletter` … `\makeatother` で書く．
  - どうしても共有ファイルの変更が必要なら，自分では変更せず，最後の報告にその内容を書く．
- **記号**: まず本の記号のマクロ（`tex/notation.sty` など）を見て，既存のマクロを使う．新しいマクロは `\newcommand` で `tex/notation/<本文のファイル名>.tex` に書く（他の章と名前がぶつかったら，まとめるときにエラーで分かる）．
- **章を分けた後半**（`ch01b` など）: ファイルの先頭で，前半を読み込まなくても番号が原書と一致するようにカウンタを設定する．
  ```latex
  \setcounter{chapter}{1}\setcounter{section}{2}% 次の \section が 1.3 になる
  \setcounter{equation}{N}\setcounter{figure}{M}\setcounter{footnote}{F}% 原書で前半の最後の番号
  ```
  N, M, F は原書の前半を見て数える．`make check` が番号を検査するので，ずれていれば分かる．
- **前付け・後付け**（まえがき，文献など）は `\chapter*` を使い，`\addcontentsline{toc}{chapter}{…}` で目次に載せる．
- 修正 ID は，その md で使っている最後の番号の続きから振る．
- 各担当は `make` が通る状態で，担当ブランチに push する．
- まとめるとき: 担当ブランチをまとめ用のブランチにマージし，`notation/*.tex` を `notation.sty` に統合して消す．

## 校正

原書が画像のときに行う．書いた本人の読みに引きずられないよう，書き起こしが終わったら別の担当（サブエージェント）が原稿画像と忠実版のソース（`tex/original/`）だけを見て照合する．約 12 ページごとに 1 担当とし，次を指示する．

- ソースは読むだけで編集しない．各ページの画像を実際に見て 1 行ずつ比べる．
- 細かい添字，プライム，チルダ・バー・ハットの区別，取り違えやすい文字（$d_X$ と $d_Y$，$\mu$ と $\nu$，$x$ と $y$）は画像を切り抜いて拡大して読む．
- 忠実版は原書と完全に一致しなければならない（誤植もそのまま）．
- 報告するのは，文字・記号・添字・句読点の誤りや脱落，`\term` の過不足，番号の違い，原書の明らかな数学の誤り（修正版で直す候補として）．改行，ページ割り，空きなどのレイアウトの違いは無視する．
- 指摘には原書のページ，ソースの行番号，原書の表記，ソースの表記を書く．

指摘は書いた担当が画像で確かめてから忠実版を直す．修正版がすでにあれば，`make sync` で同じ直しを修正版に取り込む．

## 証明の簡略化・補完

修正版に，原書が省いている議論の補完と，証明の簡略化を入れる．章ごとに別のセッションが書き，書いた担当とは別の担当がレビューする．担当とファイルは担当の表と同じで，修正 ID は各 md で使っている最後の番号の続きから振る．

### 対象

- 原書が「アイデアだけ」「詳細は読者に委ねる」「詳細は略す」「容易にわかる」「明らか」などとして省いている議論の補完．原書が「明らか」と書かずに飛ばしている隙間も補う．
- 明らかに短く，見通しよくなる証明への置き換え．原書の結論は弱めない（強めるのはよい）．議論の組み立てや依存の順序は変えてよい．
- 数行長くなっても読みやすくなる書き直し（方針の一文，飛ばされた中間式や不等式の理由，記号の衝突の解消，引用番号の明記など）．
- 作業の途中で気づいた原書の誤り．[conventions.md](conventions.md) の「原書の誤りを見つけたとき」に従う．原書の主張や注意そのものの誤りは，証明の補完ではなく，誤りとして直す．

次は対象外とする．

- 演習問題の解答．ただし，本文が「読者に任せる」とした補題は，同じ内容の演習問題があっても証明を入れる（演習問題はそのまま残す）．
- 文献を挙げて証明を略している標準的な定理と，節の冒頭などで文献にまとめて委ねている事実．
- 定義から 1 行で出る確認．

置き換えの基準:

- 短くなっても情報が減るもの（陽な定数や評価が消える，具体的な構成が抽象的な存在に置き換わるなど）は置き換えない．前方参照，背理法への切り替え，抽象的な結果への帰着はよい．短くした証明には，必要なら方針の一文を添える．
- 議論の最後に出た定数に合わせて最初の $\varepsilon$ などを取り直す書き方（「最初に $\varepsilon/3$ をとっておけば」など）は，最初に決めておく形（「$\delta = \varepsilon/3$ とおく」）に書き換えない．

### 書き方

- 修正版（`tex/revised/`）に直接書き，先頭に `\fixat{ID}` を置く．一覧の種類は「証明（簡略化）」「証明（補完）」とする．
- 原文にない文が 3 文以上ある補完・書き換えは［補完］［書き換え］の印で囲む（`\fixat{ID}\supplied{…}`．[conventions.md](conventions.md) の「修正版」）．
- 前に入れた修正（誤植の訂正など）を含む範囲を書き換えて，その修正が修正版から消えたときは，その ID の md の項目に「**修正版には出ない**」の欄を書く．
- **使ってよい事実**: 本書のそれより前（または後）にある定理・命題（番号で引用する）と，標準的な事実（アスコリ・アルツェラの定理，フビニの定理など）．使った事実は md の項目の「前提にした事実」に書く．循環しないことを確かめる．本書にも標準的な教科書にもない結果（原論文の中身など）が必要なら補完せず，「補えなかったこと」としてメモに書く．
- **番号**: 番号付きの式を消したら `\fixskip{equation}{数}` で番号を進める．新しく番号を付ける式・定理類は `\addtag` や `addlemma` などで (1.20a)，補題 1.2.3a の形にする（[conventions.md](conventions.md) の「番号」）．
- **証明を丸ごと書き換えるとき**: 原文の証明の中にあった `\origpage` は，書き換えた証明の中の対応する位置にも置く（`make check` が確かめる）．
- **自分で検証する**: 補完した証明は，不等号の向き，定数の依存性，部分列のとり方，極限の順序，測度の有限性や可測性の仮定を 1 行ずつ見直す．
- **md の書き方**: 各項目に「原書の証明」「修正版の証明（補ったこと）」「良くなった点」「前提にした事実」「補えなかったこと」を必要に応じて書く．
- **取り下げ**: 入れた補完を修正版から外すときは，修正版を前の文面に戻して `\fixat` を消し，md の項目と一覧表の行は残して，項目に「**取り下げ**: （理由）．補完した証明はコミット `<hash>` にある．」の欄を書く（`make check` は，この欄のある ID が修正版のソースに残っていないことを確かめる．ID の一部だけを外すときは「**一部取り下げ**」と書く）．
- 共有ファイル（「並列作業」の項），忠実版（`tex/original/`）と他の担当のファイルは編集しない．忠実版の書き起こしの誤りに気づいたときは，ほかに必要な変更と同じく，最後の報告に書く．

### レビュー

書き終えたら，書いた担当とは別の担当（サブエージェント）が，ソースと `corrections/` だけを見てレビューする．書いた担当の説明や結論は渡さない．レビューを頼むときは，次の観点をすべて依頼文に含める．

- 新しく入れた証明を 1 行ずつ確かめ，誤り，議論の隙間，循環した引用を指摘する．参照先の主張も実際に読む．
- 前提にした事実が本書の範囲（または標準的な事実）にあるか．
- 忠実版が変わっていないか．
- 見つかった原書の誤りが本文に反映されているか，注記したものが本当に直せないか．
- その章の書き起こしのときに入れた修正のうち，種類が「論理」のものと数式の修正を，主張が正しいか，より小さな直し方がないかの観点で検証する．直した形を使っている他の箇所の議論が通るかも確かめる．
- 置き換えた証明が原書の証明より読みやすいかも判定する（短くなっても追いにくくなったものは差し戻す）．

指摘は「誤り」「隙間」「体裁」に分け，誤りには反例か理由を書く．指摘は書いた担当が確かめてから反映する．直さなかった指摘は，理由を md のメモに残す．

担当が終わったら，まとめ役はさらに別のサブエージェントに，担当ブランチの最終検証をさせる（変更の範囲，`make` と `make check`，新しい証明の数学的な正しさ，対象の選び方）．まとめ役は差分を自分で読み込まず，検証の結論だけを受け取って，問題があれば担当に差し戻す．
