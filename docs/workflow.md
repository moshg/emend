# 作業の進め方

作業の手順を書く．書き方は [conventions.md](conventions.md) に，担当の表など本ごとの事情は本のリポジトリの `docs/book.md` にある．注意点と制約はレビュー担当が読む [review.md](review.md)（本ごとのものは `docs/book-review.md`）にあり，作業する担当は読まない．各作業の終わりにレビューを頼み，指摘を受けて直す．

## レビューを頼む

`reviewer` エージェント（本のリポジトリの `.claude/agents/reviewer.md`）に頼む．

- 依頼文には，種類（「校正」「原書の誤りの修正」「証明の簡略化・補完」「担当ブランチの最終検証」）と範囲だけを書き，自分の説明や結論は書かない（例: 「証明の簡略化・補完のレビュー．範囲は `tex/revised/ch03.tex` と `corrections/ch03.md` の 3-12 以降．」）．
- 指摘は自分で確かめてから反映する．原書の誤りの修正と証明の簡略化・補完のレビューで反映しなかった指摘は，理由を md の「修正しなかった点・メモ」に書く．
- `reviewer` を呼べない（本のリポジトリにまだ置いていない，エージェントの一覧に出ない）ときは，汎用のサブエージェントに `common/agents/reviewer.md` を読ませて頼む．
- サブエージェントは `reviewer` を呼べないので，サブエージェントに作業させたときは，呼び出した側が頼む．

## `make` の結果

- `make` はビルドの後に `make check` を行う．NG なら直す．忠実版で「ラベル名の番号」と「実際の番号」が違うと言われたら，書き起こしで定理や式を取りこぼしたか重複させている．

## 新しい章を書き起こす

1. `tex/original/<名前>.tex` を作り，原書どおりに書き起こす（原書の誤りもそのまま）．図は `tex/figures/` に TikZ で描く．`tex/main.tex` は全章のファイルを読み込むように書いてあり，ファイルを置けば読み込まれる（`tex/main.tex` は編集しない）．
2. 書き起こしながら気づいた原書の誤りは，`corrections/<名前>.md` に書きためる．
3. 原書が画像なら，「校正」をする．
4. `make sync` で忠実版を修正版に写す（新しいファイルは `tex/revised/<名前>.tex` にそのまま写される）．
5. 書きためた誤りを，「原書の誤りを直す」の手順で修正版で直す．
6. `make` でビルドとチェックを行い，ソースと `tex/original-sync.json` をコミットする（PDF はコミットしない）．

校正が済んだ忠実版は凍結する．以後は「忠実版を直す」のときだけ変える．

## 校正

原書が画像のときに行う．

1. 約 12 ページごとに 1 回，`reviewer` に校正を頼む．依頼文には，原書のページ，画像の場所，忠実版のファイルを書く（例: 「校正．原書 pp.13–24（画像の場所），`tex/original/ch02.tex`．」）．いくつかをまとめて並列に頼んでよい．
2. 指摘を画像で確かめる．書き起こしの誤りは「忠実版を直す」の手順で直し，原書の数学の誤りは `corrections/<名前>.md` に書きためる．

## 忠実版を直す

書き起こしの誤り（訳の本では誤訳，訳し落とし，訳語の変更）を見つけたときと，レイアウトを整えるときに行う．原書の誤りの修正や証明の簡略化・補完の途中で書き起こしの誤りに気づいたときは，忠実版は直さずに最後の報告に書く．

1. 忠実版（`tex/original/`）を直す．
2. `make sync` で同じ直しを修正版に取り込む．`make sync` は `git merge-file` による 3-way マージで，最後に取り込んだときの忠実版を `tex/original-sync.json` に記録している．
3. 修正版の同じ行も直してあれば，衝突として `<<<<<<<` … `>>>>>>>` が残る（段落を 1 行に書いていれば，同じ段落に修正があると段落ごと衝突する）．手で直してから `make sync` を実行し直すと，取り込み済みとして記録される．衝突をやり直したいときは，修正版のファイルと `tex/original-sync.json` の両方を戻す（修正版だけ戻すと，忠実版の直しが入らないまま取り込み済みになる）．
4. 直しと取り込みだけで 1 つのコミットにする．

## 原書の誤りを直す

直すのは，数式の誤植，誤字・脱字，人名や英語の綴りの誤り，記法の不統一，論理的な食い違い，成り立たない主張，証明の議論にある原書が明示していない穴である．

1. 修正版（`tex/revised/`）で直し，直した箇所の先頭に `\fixat{ID}` を置く．ID は，その md で使っている最後の番号の続きから振る．
2. 数学的な誤りは，反例を探す，文献を確かめる，計算し直すなどで正しい形を決めて直し，その主張や式を使っている箇所（他の章も `grep` で探す）も同じ ID で合わせて直す．直せないときは注記する．
3. 他の担当のファイルも直す必要があるときは，変えずに最後の報告に書く．
4. `corrections/<名前>.md` に一覧の行と項目を書く．
5. `make` が通ったら，`reviewer` に「原書の誤りの修正」のレビューを頼む．

## 証明の簡略化・補完

修正版に，原書が省いている議論の補完と，証明の簡略化など本を理解しやすくする改善を入れる．章ごとに別のセッションが書き，担当とファイルは担当の表と同じ．

1. 章を読み，入れる所を選ぶ．入れるのは次のようなものである．
   - 省かれた議論を補う: 原書が「アイデアだけ」「詳細は読者に委ねる」「詳細は略す」「容易にわかる」「明らか」などとして省いている議論や，断りなく論理が飛躍している所を補う．
   - 証明をもっと簡単にする: 明らかに短く，見通しよくなる証明に置き換える．議論の組み立てや依存の順序は変えてよい．短くした証明には，必要なら方針の一文を添える．
   - 構成によって本をもっと簡単にする: 定義や補題を使われる所へ移す，章をまたいで繰り返される議論を 1 つの補題にまとめる，役目のなくなった補題を消す．
   - 証明を複雑にせず結論を強める: 主張を強め，強めた分を修正版の中で証明する．
   - 定義をより直感的にする: 定義を，本書の仮定のもとで同値で直感的な形に書き換える．定義の直後に意味の説明や例を置く．主張や仮定も，同値で簡潔な形に書き換えてよい．
   - その他理解しやすくする: 数行長くなっても読みやすくなるなら書き直す（方針の一文，飛ばされた中間式や不等式の理由，記号の衝突の解消，議論の要になる結果の引用番号の明記など）．
   - 演習問題の解答，文献を挙げて証明を略している標準的な定理（節の冒頭などで文献にまとめて委ねている事実を含む），定義から 1 行で出る確認は入れない．ただし，本文が「読者に任せる」とした補題は，同じ内容の演習問題があっても証明を入れる（演習問題はそのまま残す）．
2. 修正版に直接書き，先頭に `\fixat{ID}` を置く．主張・定義・仮定を書き換えたり強めたりしたときは，その記述を使っている箇所（他の章や補完の中も `grep` で探す）も同じ ID で直す．使うのは本書の定理・命題（前でも後でもよい）と標準的な事実で，それで足りないときは補わずに md の「補えなかったこと」に書く．
3. 途中で気づいた原書の誤りは，「原書の誤りを直す」の 1〜4 で直す（レビューは補完のレビューで一緒に頼む）．
4. 補った証明を自分で 1 行ずつ見直し，md に一覧の行と項目を書く．
5. `make` が通ったら，`reviewer` に「証明の簡略化・補完」のレビューを頼む．

## 並列作業

章ごとに別のセッション・別のブランチで並列に作業し，最後に 1 本のブランチにまとめてから main にマージする．章とファイルの対応は担当の表に従う（本文のファイル名は `tex/original/` と `tex/revised/` で同じ）．

- 自分の担当のファイル（担当の表の本文・記号・修正のまとめ・`tex/figures/` の担当の図）と，`make sync` が書く `tex/original-sync.json` だけを変える．共有ファイル（`tex/main.tex`，`tex/notation.sty`，本の sty，`README.md`，`docs/`，`common/`，`.github/`，`Makefile`）や他の担当のファイルの変更が要るときは，変えずに最後の報告に書く．
- 記号は，本の記号のマクロ（`tex/notation.sty` など）にあるものを使う．新しいマクロは `\newcommand` で `tex/notation/<本文のファイル名>.tex` に書く．
- 担当の中だけで必要な書式の調整（付録の番号の付け方など）は，担当の本文ファイルの中に `\makeatletter` … `\makeatother` で書く．
- 章を分けた後半（`ch01b` など）は，ファイルの先頭で，前半を読み込まなくても番号が原書と一致するようにカウンタを設定する（修正版の前半で番号を変えたら，修正版の後半はそれに合わせて直す）．
  ```latex
  \setcounter{chapter}{1}\setcounter{section}{2}% 次の \section が 1.3 になる
  \setcounter{equation}{N}\setcounter{figure}{M}\setcounter{footnote}{F}% 原書で前半の最後の番号
  ```
  N, M, F は原書の前半を見て数える．
- `make` が通る状態で，担当ブランチに push する．

### まとめる

1. 担当が終わったら，担当ブランチごとに `reviewer` に「担当ブランチの最終検証」を頼む．まとめ役は差分を自分で読み込まず，結論だけを受け取って，問題があれば担当に差し戻す．
2. 担当ブランチをまとめ用のブランチにマージする．`tex/original-sync.json` が衝突したら，`make sync` をやり直さず，両方のブランチの行をすべて残し，両方にあるファイルの行は，そのファイルを変えた側の値を取る（`git hash-object tex/original/<名前>` と一致する）．
3. `tex/notation/*.tex` を `tex/notation.sty` に統合して消す（他の章と名前がぶつかっていれば，ビルドがエラーになる）．
