# 書き起こしの規約

新しい章を TeX 化するときも，証明の簡略化・補完をするときも，この規約に従う．本ごとに決めること（番号の付け方，文献の表示，記号，担当の表など）は本のリポジトリの `docs/book.md` にあり，この規約と食い違うときはそちらに従う．

ここでいう「原書」は TeX 化する元の本，「忠実版」は原書どおりの版（`original.pdf`），「修正版」は誤りを直し，証明の簡略化や補完を入れた版（`revised.pdf`）である．訳の本では，忠実版は原書に忠実な訳になる．

## 番号とラベル

- 定理・定義・系・注意・例などの番号の付け方（節ごとの共通番号か，章ごとか）は原書と同じにする．
- ラベルは **`接頭辞:原書の番号`** で付ける．

  | 対象 | 例 |
  |---|---|
  | 定理・定義など | `\label{thm:1.1.1}`（種類によらず `thm:`） |
  | 数式 | `\label{eq:1.12}` |
  | 図 | `\label{fig:1.1}` |
  | 章・節・小節 | `\label{ch:1}`, `\label{sec:1.1}`, `\label{sec:1.1.2}` |
  | 付録 | `\label{app:A}`（付録の中の定理は `thm:A.1`，式は `eq:A.1`） |

- `make check` が「ラベル名の番号」と「実際に振られた番号」の一致を検査する．ずれていれば，書き起こしで定理や式を取りこぼしたか重複させている．
- 複数行で番号が 1 つの式は `equation` の中に `aligned` や `gathered` を置く．

## 参照

- 参照には `\ref` ではなく `\bref{thm:1.1.2}`，数式は `\beqref{eq:1.1}`（括弧付き）を使う．「定理\bref{thm:1.1.2}」「\bref{sec:1.2}節」のように，種類の語は本文に書く．
- 参照先の章がまだ TeX 化されていなければ，ラベル名の番号（`1.1.2`）がそのまま表示される．その章を TeX 化すれば自動的にリンクになる．
- 文献は `\bcite{…}` で引く．

## 忠実版と修正版

2 つの版は別のソースである．

- 忠実版は `tex/original/<名前>.tex`．原書どおりの書き起こし（原書の誤りもそのまま）で，校正が済んだものを凍結している．
- 修正版は `tex/revised/<名前>.tex`．忠実版を写したものに修正を入れる．修正版は普通の TeX として直接編集する．原書の誤りの修正や証明の補完のときは，忠実版は変えない．
- **忠実版を直すのは，書き起こしの誤り（訳の本では誤訳，訳し落とし，訳語の変更）が見つかったときと，版面を整えるときだけ**．直したら `make sync` で同じ直しを修正版に取り込み，それだけのコミットにする．`make sync` は `git merge-file` による 3-way マージ．
  - 修正版の同じ行も直してあれば，衝突として `<<<<<<<` … `>>>>>>>` が残る（段落を 1 行に書いていれば，同じ段落に修正があると段落ごと衝突する）．手で直してから `make sync` を実行し直すと，取り込み済みとして記録される．衝突をやり直したいときは，修正版のファイルと `tex/original-sync.json` の両方を戻す（修正版だけ戻すと，忠実版の直しが入らないまま取り込み済みになる）．
  - 取り込みを忘れたり，衝突を解いていなかったりすれば `make check` が NG にする．最後に取り込んだときの忠実版は `tex/original-sync.json` に記録してある．
  - ブランチをまとめるときに `tex/original-sync.json` が衝突したら，`make sync` をやり直さず，各ファイルの行を両側から残し，同じファイルの行はそのファイルを変えた側の値を取る（`git hash-object tex/original/<名前>` と一致する）．

## 修正版

- 原書を直した箇所には，その先頭に目印 `\fixat{ID}` を置き，直した文を書く．`\fixat` は何も出力せず，巻末の修正箇所の索引にページを載せ，索引からのリンク先になる．数式中でも使える．
- ID は `章-連番`（`4-01`, `4-02`, …）．一度振った ID は振り直さない．新しい ID は，その md で使っている最後の番号の続きから振る．
- 1 つの修正が複数箇所にわたるときは，それぞれの箇所に同じ ID の `\fixat` を置く．長い書き換えで，原文がそのまま（80 字以上）残った所より後にも変更が続くときは，その変更の近くにも同じ ID の `\fixat` を置く．`make check` は，近く（前後 80 字以内）に `\fixat` がなく，`\supplied`・`\rewritten` の中にもない変更を「要確認」として表示する（警告で，`make check` は失敗しない）．ID なしで修正版を直したり，書き起こしの誤りを忠実版でなく修正版で直したりしていないかを確かめる．
- `\fixat` は見出しの引数（`\section{…}`，`\begin{theorem}[…]`）や `\item[…]` の中に置かない（目次やしおりに紛れ込む）．見出しを直したときは見出しの直前か直後に置く．
- `corrections/<章のファイル名>.md` の一覧の表に 1 行足し，`### ID 見出し` の項目を書く（書式は `common/example/corrections/ch01.md` にならう）．TeX と md の ID の過不足は `make check` が検出する．後の修正で置き換えた範囲に入って修正版から消えた ID は，md の項目に「`- **修正版には出ない**: X-YY で置き換えた範囲にある．`」と書く（`make check` はこれがあれば過不足とみなさない）．
- 直すのは，数式の誤植，誤字・脱字，人名や英語の綴りの誤り，記法の不統一，論理的な食い違い，成り立たない主張．
- 主張・定義・仮定の書き方は，本書の仮定のもとで同値であり，明らかに簡潔になるなら書き換えてよい．md の一覧の種類は「記述（簡略化）」とし，項目に「同値である理由」（使った本書の仮定を含む）を書く．その記述を使っている箇所は，他の章や補完の中も grep して同じ ID でそろえて直す．
- 原書の数学的な誤りの扱いは，下の「原書の誤りを見つけたとき」に従う．
- 証明の簡略化と，原書が省いている証明の補完も，修正版に `\fixat{ID}` を置いて入れる（md の一覧では種類を「証明（簡略化）」「証明（補完）」とする．進め方は [workflow.md](workflow.md) の「証明の簡略化・補完」）．
- 原書にない議論には印を付ける．種類に「補完」か「注記」を含む修正は［補完］…［補完ここまで］（`\supplied{…}`），「簡略化」か「書き換え」を含む修正は［書き換え］…［書き換えここまで］（`\rewritten{…}`）で，修正した範囲の全体を囲む．
  - 付けるのは原文にない文が 3 文以上あるときだけで，1〜2 文の追加や言い換えには付けない．
  - 印の中に別の印は付けない．
  - 印は `\fixat{ID}` の直後に置き（`\fixat{1-02}\supplied{…}`），修正が 1 つの証明環境だけのときは環境の中に置く（`\fixat{1-02}\begin{proof}\supplied{…}\end{proof}`）．巻末の索引のその ID にも「（補完）」「（書き換え）」が付く．
  - 置き場所と種類は `make check` が検査する．`make check` は，印のない修正で忠実版にない文が 3 文以上あるものも「要確認」として表示する（忠実版の文を少し直しただけの文は数えない）．これは警告で，`make check` は失敗しない．

### 原書の誤りを見つけたとき

主張・式・定義が成り立たない，または証明の議論に原書が明示していない穴があるときは，修正版の本文に必ず反映する．反映のしかたは次の 2 つで，**直すのが基本**．

1. **正しい形に直す**（修正版で直し，`\fixat{ID}` を置く）．次を確かめたうえで直す．
   - 反例があるか，誤りである理由がはっきりしている．
   - 正しい形が一つに決まる（標準的な形，または仮定の最小限の追加・結論の最小限の弱め）．文献で確かめられるなら確かめる．
   - その主張や式を使っている箇所（他の章も `grep` で探す）の議論が，直した形でも通る．通らなければ，そこも合わせて直す．

   これらは反例を探す，文献を確かめる，計算し直す，などで調べて判断する．
2. **注記する**（修正版に `\fixat{ID}（注：……）` を足す．md の一覧の種類は「注記」）．次のどちらかで直せないときに限る．
   - 正しい形の候補が複数あり，どれか一つに決められない．
   - 直す・補うのに本書の範囲を超える結果（原論文の中身など）が必要．

   md の項目には「**直さなかった理由**」の欄を書く（`make check` が検査する）．分かれば「**正しい形の候補**」も書く．

md の「修正しなかった点・メモ」には，誤りではない記述についての注意，原書が省略を明示していて補えなかった（またはまだ補っていない）証明，修正・注記の背景説明を書く．原書の誤りに触れるときは，対応する ID を書く．`make check` は，「偽」「成り立たない」「穴」などを含むのに ID のないメモを「要確認」として表示する（失敗にはしない）．

### 番号

修正版の定理・式・脚注の番号は，原書（忠実版）と一致させる．`make check` が，2 つの版に共通するラベルの番号と，各章の終わりのカウンタの値（節・式・脚注など．ラベルのない式や脚注も含む）が同じかを確かめる．脚注は修正版で足したり消したりしない（補足は本文に書く）．

- 証明を書き換えて番号付きの式や定理を消したときは，その後に `\fixskip{equation}{2}` のように消した数だけ番号を進める．
- 書き換えの中で新しく番号を付ける式は，番号を進めないよう `\begin{equation*}\tag{1.20$'$}\label{rev:1.20p}` のように書く（同じ場所の 2 つ目は $''$，ラベルは `rev:1.20pp`）．ラベルの接頭辞は `rev:`（`make check` の番号検査の対象外）．`equation` 環境で `\tag` を使うと hyperref のアンカー名が重複することがあるので `equation*` を使う．原書の番号を残すときは `\begin{equation*}\tag{1.22}\label{eq:1.22}` でよい．定理・補題などの番号付き環境は新しく作らない．
- 原文の中のラベル（`\label{eq:1.5}` など）は，修正版でも同じ式や定理に残す（参照が忠実版と同じ番号を指すように）．
- 書き換えた範囲の中に原書のページ境界があるときは，修正版の対応する位置にも `\origpage` を置く（`make check` が確かめる）．

## その他

- 用語の太字（原書の太字）は `\term{...}`．
- 原書のページ境界には `\origpage{2}` を置く（余白に「原 p.2」と出る）．数式の中や脚注の中には置けないので，近くの本文に置く．見出しの直前に置くと空行ができ，定理環境の直後に置くと見出しが前のページに取り残されることがあるので，本文か最初の `\item` の先頭に置く．
- 記号は本の記号のマクロ（`tex/notation.sty` など）を使う．すでにあるマクロは必ずそれを使う．

## 新しい章を追加する手順

1. `tex/original/<名前>.tex` を作り，上の規約に従って原書どおりに書き起こす．図は `tex/figures/` に TikZ で描く．原書の誤りはここでは直さず，`corrections/<名前>.md` に書きためる．`tex/main.tex` には全章分の差し込み口があり，ファイルを置けば自動的に読み込まれる．**main.tex は編集しない**．
2. 原書が画像なら，[workflow.md](workflow.md) の「校正」をする．
3. `make sync` で忠実版を修正版に写す（新しいファイルは `tex/revised/<名前>.tex` にそのまま写される）．修正版で md に書いた誤りを直し，`\fixat{ID}` を置く．
4. `make` でビルドとチェックを行い，ソースと `tex/original-sync.json` をコミットする（PDF はコミットしない）．
